1. Завершить модель прав
Зафиксировать доступ:
WORKER:Android — регистрация заказов, коробки, партии;
Web — клиенты, заказы, манифесты и рабочая аналитика.

ADMIN:сотрудники и блокировка аккаунтов;
настройки склада;
справочники;
аудит и критические исправления.

CLIENT:профиль, заказы, уведомления и аналитика.

Добавить управление сотрудниками во фронтенде.
2. Доработать заказы
Сделать реальные Web-страницы вместо демонстрационных данных:
поиск и фильтрация заказов;
просмотр и исправление заказа;
состав из справочника;
описание товара;
стоимость и валюта;
вес и размеры;
клиент, коробка и партия;
история изменений.
Клиенту показать состав, описание и стоимость в личном кабинете.
3. Справочники
В административных настройках добавить управление:
составом заказа;
складами;
странами;
статусами заказов;
валютами;
при необходимости типами упаковки.
Удалять используемое значение нельзя — его можно только отключить.
4. Коробки и партии во Web
Реализовать настоящие страницы:
список и поиск коробок;
состав коробки;
общий и собственный вес;
перемещение заказа между коробками;
создание и завершение партии;
список коробок и заказов партии;
проверка незаполненных обязательных данных.
Android при этом остаётся основным инструментом сканирования.
5. Манифесты
Доработать документ:
номер и дата;
склад и страна;
все необходимые данные заказа и клиента;
итоговый вес, количество коробок и заказов;
общая объявленная стоимость по валютам;
экспорт в PDF и Excel;
печать;
повторное скачивание неизменяемого документа.
Для исправления ошибок — создавать новую версию манифеста, не изменять старую.
6. Клиенты
Во фронтенде добавить:
создание и редактирование;
телефон, email и адрес;
блокировку кабинета;
сброс пароля;
историю заказов;
статистику;
уведомления;
запрет изменения клиентского кода клиентом.
7. Переключение Android
Когда API будет функционально готов:
Добавить адрес нового API в тестовую конфигурацию Android.
Проверить все сценарии сканирования.
Сравнить ответы нового и старого API.
Провести тестовую работу на одном устройстве.
Переключить рабочую сборку.
Некоторое время оставить старый API как резервный.
8. Надёжность и размещение
Перед реальным запуском:
восстановление access-токена через refresh-токен;
отзыв сессий и блокировка сотрудников;
журнал всех изменений;
резервное копирование PostgreSQL;
централизованные логи;
обработка ошибок;
HTTPS и секреты;
staging-окружение;
автоматические тесты и CI/CD.
Ближайший практический шаг
Сейчас лучше начать с реального раздела заказов во Web: список из базы, поиск, просмотр и редактирование состава, описания, стоимости, веса и клиента. После него — реальные коробки и партии, затем PDF/Excel-манифест.
Монорепозиторий пока сохраняем. Разделять Android, API и Web на отдельные репозитории имеет смысл только после успешного переключения Android на новый backend.
